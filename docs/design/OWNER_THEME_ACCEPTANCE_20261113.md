## 사용자 결정

- Genesis / Warm Family / Spatial 테마 방향과 배치를 승인한다.
- 이미지가 뿌옇게 보이는 문제는 남아 있다. `UI-SHARP-01` / P2로 후순위 보정한다. 고해상도 원본 없이 잃어버린 디테일을 복원했다고 주장하지 않는다.
- 개인정보·본인 동의/서명/날짜는 사용자가 직접 작성한다. 작성 완료/접수 완료로 자동 전환하지 않는다.
- 서명키 개념과 사용자 절차를 먼저 안내한다. 키 생성·비밀번호 취급·release 서명 완료 승인은 아직 아니다.
- 다음 개발은 기능별 INPUT → PROCESSING → OUTPUT 계약을 먼저 만들고, 계약별 구현과 실제 검증을 연결한다. 관련 문서: `FUNCTIONAL_DEMO_IPO_PLAN.md`.

## 증거 시점 처리

기존 native receipt의 `ownerVisualApprovalReceived=false`는 검증 당시 기록이다. 과거 원시 receipt를 승인받았던 것처럼 덮어쓰지 않고 현재 승인 결정을 이 파일로 추가한다. 이 승인은 실제 TTS 성공, 실제 차량 제어, 안전/서명/접수 완료를 뜻하지 않는다.
