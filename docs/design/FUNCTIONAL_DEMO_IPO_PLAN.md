# 기능별 시연 Input → Processing → Output 계약

작성: 2026-11-13 KST · 최초 기준 구현: cdfd6ef. 이 문서는 설계 계약이며, 최신 구현·실행 결과와 남은 미검증 항목은 `FAMILY_JOURNEY_VERIFICATION_20261113.md`를 따른다. 모든 계약 항목이 완료됐다는 뜻은 아니다.

## 사용자 결정과 우선순위

- 3테마 방향/배치 승인. 승인된 메인 화면을 다시 디자인하지 않는다.
- 이미지 흐림은 UI-SHARP-01/P2 후순위로 관리한다. 기능·음성·안전·제출 작업을 막지 않는다.
- 개인정보/본인 동의/서명은 사용자 직접 작성. APK 서명키는 동의서 서명과 별개다.
- 최신 결정: 서명키 생성·설정은 기능 구현·검증 뒤로 보류한다. 지금 키 준비를 사용자에게 요구하지 않는다. release 서명 자체의 최종 gate는 유지한다.
- 우선순위: 관찰 가능한 기능 시연 → 실제 음성/실패 처리 → 안전·복귀 → release/영상 → 이미지 선명도.
- 기능은 소리·시각으로 확실하게 관찰할 수 있어야 한다. `COMPETITION_SHOWCASE_PROPOSAL.md`의 대표3장면·짧은 전후 강조·실제 앱 소리·선택형 기술 설명은 사용자가 구현을 승인했다. 기존 정확성/안전 검증과 함께 수행한다.

## 진실성·표시 계약

1. 센서/내비/시선/호흡/체압/기상 데이터는 현재 **로컬 시나리오 fixture**다. 마이크·카메라·실제 건강 상태를 측정했다고 표시하지 않는다.
2. 좌석 온도·풍량·열선·마사지·조명·가상 존 음량은 **Mock 모델 변화**다. 차량 명령은 전송하지 않는다. ANC·독립 음장·실제 내비 경로 변경이라고 부르지 않는다.
3. Vehicle 경로는 **SDK read-only**로 따로 시연한다. 현재 Console→DDS→callback→UI 왕복은 미검증이다.
4. 앱의 실제 TTS/MediaPlayer 출력은 Mock 차량 제어와 별개다. `storyPlaying=true`, 합성 callback, 자막, 재생 요청만으로 실제 소리가 났다고 판정하지 않는다.
5. 출력은 `Mock 모델 반영`, `자막 표시`, `음성 합성`, `앱 재생 시작`, `실제 청취 확인`을 각각 기록한다. 실패는 FAILED/BLOCKED/NOT_RUN으로 구분한다.
6. 현재 음성 범위는 앱의 한국어 안내/동화 **출력**이다. 사용자 음성명령 인식은 현재 구현으로 주장하지 않는다.
7. 고정 confidence %, 실제 ANC/내비 무간섭 보장·0dB·실측 없는 성능 수치는 시연 성공 근거에서 제외한다.

## 시연 UI와 증거 설계 계약

- 현재 구현은 정차용 헤더의 `가족 여정` 진입점과 선택형 상세 설명을 사용한다. 메인 3테마 배치와 원본 artwork를 유지한다.
- 장면별로 INPUT 값/출처 → PROCESSING 조건별 true/false·보호 사유 → OUTPUT 전후 값을 표시한다. 고정 설명문만 띄워 동작 증거로 삼지 않는다.
- 모델 변경과 실제 오디오를 별도 칸에 둔다. `[모의 입력]`, `[Mock 제어]`, `[실제 SDK 조회]`, `[실제 앱 오디오]`, `[미검증]` 배지를 출력별로 붙인다.
- 시연 액션 ID는 음성 eventId와 분리한다. 풍량/탭 같은 조작 때문에 같은 안내가 반복 재생되지 않게 한다.
- 성공 조건이 맞지 않는 입력도 보여 준다. 규칙 false일 때 제어/음성 이벤트가 발생하지 않아야 한다.
- 안전하게 중지 가능하며, 재시연은 명시적 사용자 액션이다. 자동 진행은 음성 완료/실패를 확인하고 진행하며 기존 고정 7초 전환으로 안내를 잘라먹지 않게 한다.
- 증거는 app/flavor/source SHA·case/action ID·입력·가드·before/after·음성 단계·기기/실제 청취 여부를 묶는다. 개인정보/키/인증정보를 담지 않는다.

## 구현·검증 순서

1. **S1 — 세로 슬라이스:** F01 한 장면의 실제 UI 조작→로컬 규칙→Mock before/after→자막/오디오 상태→중지. 먼저 실패 시험으로 trace/취소 누락을 재현한다.
2. **S2 — 음성 핵심:** F07/F08. init/엔진/오프라인 한국어 voice/합성/PCM/focus/재생을 분리 진단. SDK 공식 지원 경로와 비교하되 새 엔진·계정·라이선스·비용은 승인 전 도입하지 않는다. 기존 안내문의 가상 공조/조명/음악 조치를 실제 수행처럼 읽는 표현과 근거 없는 사실·차단 보장을 검토하고 모의 시연 범위를 음성에도 반영한다.
3. **S3 — 나머지 기능:** F02~F06/F09~F11과 경계값/중복/역순 조작. 공통 Context/trace 출처를 정합화한다. 실제 차량 쓰기 API를 추가하지 않는다.
4. **S4 — 통합·안전:** F12~F14, AudioFocus deny/loss/duck/recovery, background/resume/process 복귀, 실제 주행/unknown/창 크기. 기존 3테마·1.5배 글씨 회귀.
5. **S5 — 제출 후보:** 사용자 소유 release 키로 서명·설치 검증 → 같은 APK로 최신 영상/시연 대본/기획서 → 최종 접수 승인. 이미지 흐림은 이후 잔여 시간에 보정.

단계마다 한 동작씩 RED→GREEN→회귀→실제 화면/필요 시 소리 검증을 한다. 전체 가상의 시험을 먼저 만들고 결과를 채우지 않는다. OpenHands는 UI/trace·음성/안전·독립 검증 역할로 최대3팀, Hermes가 공통 API/통합과 Mac 직렬 실행을 관리한다. 이 문서 작성만으로 팀이 실행 중이라고 표시하지 않는다.

## 완료 판정

- 표의 각 기능에 성공/반례/중지·복귀 근거가 있어야 한다. NOT_RUN을 PASS로 바꾸지 않는다.
- 음성 성공 = 본문 일치 + 합성/재생 단계 + 실제 청취/캡처 확인. TTS 실패 시 자막 fallback은 별도 성공이며 음성 성공이 아니다.
- Mock 성공은 실제 차량 제어 성공이 아니다. SDK read-only 왕복은 별도 증거다.
- 실제 음성 미성공·실차 미지원·OEM Suspend 미검증이 남으면 명시하고 제출 소개와 영상도 같은 범위로 맞춘다.
