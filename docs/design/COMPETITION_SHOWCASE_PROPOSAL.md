# 공모전 시청각 시연 강화 — 승인된 구현 계획

작성 2026-11-13 KST. 상태: **사용자 구현 승인, 구현·검증 진행**. 승인 범위는 대표3장면·짧은 전후 강조·실제 앱 소리·선택형 기술 설명이다. 사전녹음 대체·새 배경음악·비용/계정/약관 동의는 별도다. 기존 기능 정확성/음성 경로/안전 검증을 함께 수행한다. 서명키 생성/설정은 기능 검증 뒤로 보류한다.

## 추천 방향

**제품 경험을 먼저 보여주고, 기술 근거는 필요할 때 펼친다.** 승인된 3테마를 다시 디자인하지 않는다. 대표 영상에는 Warm Family를 우선 제안하고 Genesis/Spatial은 선택 화면으로 유지한다. 테마 선택 자체보다 가족에게 일어난 변화가 주인공이다. 이 방향이 수상이나 가산점 크기를 보장하는 것은 아니다.

공식 1차 평가 항목은 차량특화성·창의성·기술활용성·사업성이다. 시연영상/소스+APK는 선택 가산점 자료다. 따라서 이 앱에는 기능 버튼 수나 애니메이션 양을 늘리는 것보다, 가족의 문제→앱 행동→관찰 가능한 결과와 실제 Pleos 연계 증거를 보여주는 편을 추천한다. 예상 MAU/유지율/불편 감소 수치를 만들어내지 않는다.

## 승인된 연출과 별도 결정 항목

| 제안 | 관객이 보는/듣는 것 | 경계/비용 | 결정 상태 |
|---|---|---|---|
| A. 가족여정 3장면 | 아이 소란→수면→부모님 케어로 이어지는 짧은 이야기. 목적을 한 문장으로 전달 | 시간축약/상황전환은 시연 fixture임을 표시. 전체14기능 시험은 별도 유지 | 구현 승인 |
| B. 전후 차이 강조 | 동작한 좌석만 짧게 강조하고 상태·버튼·모의제어 before/after 표시 | 원본 bitmap/기존 glow 사용. 계속 움직이는 장식·플래시 금지. 시연 입력 소음82→35를 실제 저감 성과로 표시하지 않음 | 구현 승인 |
| C. 실제 앱 음성 중심 | 짧은 한국어 안내/동화가 실제 재생되고 수면 전환에서 멈추는 대비 | 과도한 음량/효과음 경쟁 없음. narration은 모의 HVAC를 실제 제어했다고 말하지 않음. 실제 발화/중지 검증 필요 | 구현 승인·실기 검증 필수 |
| D. 즉시 이해되는 결과 | 핵심 결과 한 줄과 실제 재생/중지 상태. 실제 재생 상태와 연결된 표지만 사용 | 가짜 파형을 음성 실측으로 제시하지 않음. 긴 로그/센서 표는 펼치기 안에 유지 | 구현 승인 |
| E. 기술 확인 장면 | 실제 SDK read-only 좌석 값과 화면 갱신, 입력→규칙→출력 근거 | 실제 콜백 미검증이면 미검증 표시. SDK 로고·Mock 성공으로 대체하지 않음 | 구현/검증 및 영상 구성 승인 |
| F. 녹음 음성 대안 | 공식 TTS 경로가 끝까지 막힌 경우 권리 확인된 로컬 녹음 재생 | 실시간 TTS 성공이라고 하지 않음. 무단 음원/유료 생성/네트워크 서비스 자동 도입 금지 | 조건부 대안·별도 결정 |

대표 메시지 초안: **같은 차 안, 서로 다른 휴식.** 또는 **가족의 서로 다른 필요를 배려하는 차량 케어 경험.** 운전자 조작/피로가 실제로 줄었다는 측정 효과는 주장하지 않는다.

## 대표 영상 구성안 — 길이는 제안일 뿐 공식 제한 아님

- 도입: 가족별 불편을 짧은 한 줄로 소개. 처음부터 Mock 제어/정차 시연 범위를 명확하게 표시한다.
- 장면1 소란: 입력 preset → 2열 케어 상태 변화 → 실제 짧은 동화/안내. 버튼 클릭만으로 끝내지 않는다.
- 장면2 수면: 시간축약 모의 상황 전환 → 재생 중인 앱 음성을 중지 → 조용한 상태/Mock 좌석 변화. 무음은 재생 실패와 구별해 의도적 중지 상태로 표시한다.
- 장면3 부모님: 3열 Mock 케어와 짧은 실제 안내 → 휴게소 제안에 직접 응답. 실제 내비 목적지/경로 설정이라고 말하지 않는다.
- 근거: 실제 가능한 SDK 조회/상태 갱신과 간결한 I/P/O 확인. 실패·지원 범위는 숨기지 않는다.
- 마무리: 앱의 가치와 현재 지원 범위를 한 문장으로 정리한다.

대표 영상은 약60~90초를 제안하되, 전체 기능별 조작 영상/자동시험 근거는 따로 보관한다. 한 화면에 모든 기능을 보여주려 하지 않는다. 음성에 후반 편집으로 붙인 소리를 실제 앱 발화로 위장하지 않는다. 영상 설명 자막과 앱 자체 UI도 구분한다.

## Pleos 준수 조건 — 제안보다 우선

- 정차용 시연에서만 상세 조작·장면 전환·기술 패널을 사용한다. 주행/unknown 상태에서 제한 UI를 데모 설정으로 우회하지 않는다.
- 주행 중 시선을 끄는 자동/반복 애니메이션·화면 전환을 줄이거나 제한한다. 큰 터치 영역·명확한 대비·짧은 텍스트·최소 조작을 유지한다.
- CarUxRestrictions 및 카테고리/지역 정책을 실제로 반영한다. 현재 앱의 보수적인 제한 정책을 연출 때문에 완화하지 않는다.
- 오디오 포커스 손실/거절/duck·중요 안내에 대한 대응과 앱 background/종료 시 정책을 검증한다. 시스템 음량을 임의로 높이지 않는다.
- Driving view는 OS 소유다. 앱은 해당 영역을 가리거나 제어하지 않는다. 앱 window 안에서만 배치하고 portrait/landscape/좁은창·큰글씨를 확인한다.
- 화려한 전체화면 영상·새3D/입자·여러 BGM·음성명령 인식 같은 범위 확장은 추천 기본안에 포함하지 않는다.

## 별도로 확인한 음성 경로

현재 앱 AudioNarrator는 Android 기본 TextToSpeech 경로다. Pleos 공식 문서에는 별도 `ai.pleos.playground.tts.TextToSpeech` SDK v3.3.1과 Speech Service가 있다. `Mode.ON_DEVICE`는 문서상 네트워크·서버 앱등록이 필요하지 않으며, 기본 HYBRID와는 다르다. 이는 유망한 진단 경로이지 현 APK에서 도입/작동했다는 증거가 아니다. 기존 Kotlin/SDK/AVD 호환, 권한, 서비스 존재, 콜백, AudioFocus/취소를 확인한 뒤 최소 통합 여부를 판단한다. 새 약관동의·계정·서버 자격정보·엔진 설치·비용은 자동 진행하지 않는다.

## 실행과 승인 분리

- 기능 정확성·취소·음성 검증과 승인된 연출을 함께 구현한다. 비용/계정/새 약관 등 기존 승인 경계는 유지한다.
- 현재 작업은 OpenHands의 여정 UI·공식 오프라인 음성·대본/계약3팀으로 분리하고 Hermes가 공통 API/빌드/실기 검증을 통합한다. 작업 상태는 project operation 기록으로 관리한다.
- **제품경험 중심 3장면 + 짧은 전후 강조 + 실제 앱 소리 + 선택형 기술 설명** 조합이 승인됐다. 모든 세부 색/간격을 사용자에게 고르게 하지 않는다.
