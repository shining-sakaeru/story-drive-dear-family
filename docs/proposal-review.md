# 제안서·구현 대조 검토

검토 기준: 현재 소스와 확인된 실행 기록만으로 판단했다. 기획 의도, 코드 구현, 실제 대상 검증을 서로 다른 상태로 표기한다. 본 문서는 참가자 정보·동의·서명 양식을 대신 작성하지 않는다.

## 심사자 관점의 핵심 판정

- **구현 완료(로컬/Mock)**: 4개 좌석 상태 화면, 5대 시나리오 규칙, I-P-O 표시, 30초 Auto-Tour 상태 전환, 취소·초기화, 로컬 오디오 세션 정책이 구현되어 있다. 도메인/소스 컴파일 및 기존 acceptance 근거가 있는 범위다.
- **실제 SDK 읽기**: `pleos` 경로는 Vehicle 2.3.2를 초기화하고 Capability를 확인한 뒤 지원 좌석의 occupancy를 조회·구독하는 **read-only** 경로다. `CAR_SEATS` 권한·서비스·지원 영역·콜백 결과에 따라 실패할 수 있으며 차량 제어 API를 호출하지 않는다.
- **Mock**: 소음, 체압·수면, 우천·대화, 위치·주행시간, 공조·온열·마사지·요추·조명·창문·내비 경유·좌석별 음장·소음 차폐는 시나리오/화면용 Mock이다. 화면의 SDK 입력 표기는 실제 입력과 모의 입력을 섞어 읽히지 않도록 설명해야 한다.
- **검증 전**: 실제 Virtual Console 왕복, CarUxRestrictions 전환, AudioFocus 거절·손실·duck, 한국어 offline voice 청취, OEM Suspend/Resume, 좁은 창·portrait와 장시간 성능은 이 세션에서 확인하지 않았다. 공식 이미지에는 한국어 offline voice 미지원·자막 시연 상태가 표시되어 있다.

## 제안서에 유지할 설명 순서

1. 문제와 대상 가족을 기획 목표로 제시한다.
2. 현재 구현: Mock 독립 데모와 로컬 규칙을 설명한다.
3. 실제 SDK: 좌석 occupancy read-only만 별도 영역에서 표시한다고 명시한다.
4. 한계: 차량 제어·실제 센서·독립 음장·실제 내비·실제 음성 청취는 미구현 또는 미검증이라고 쓴다.
5. 검증 계획: Virtual Console, CarUxRestrictions, AudioFocus, portrait/좁은 창, Suspend/Resume을 후속 gate로 제시한다.

## 금지할 표현

- 실제로 읽지 않은 센서 또는 사용하지 않은 SDK를 “연동”이라고 쓰지 않는다.
- Mock 수치로 안전성·피로·수면·스트레스 효과를 입증했다고 쓰지 않는다.
- 공용 스피커 출력을 멀티존·방향성 음장·소음 차폐라고 쓰지 않는다.
- 영상·저장소 링크·사용자 수·매출·계약·심사 통과를 만들어 쓰지 않는다.
- 실명, 계정명, 연락처, 프로젝트 ID, SDK client ID, credential을 자료에 넣지 않는다.
