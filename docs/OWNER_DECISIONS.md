- 서버 최신 프로젝트 소개 초안: `submission/StoryDrive_DearFamily_application_SERVER_REVIEW.docx` (Git 제외). 원본 DRAFT와 Mac Downloads 원본은 변경하지 않았다.

## 2. Mac 재개와 미완료 기기 검증

- 2026-11-13 기준 사용자의 재개 허용 후 최신 UI native 검증까지 수행했다. 아래의 재개 전 제한은 이후 사용자가 다시 중지했을 때도 적용한다. 다음 실제 작업 전에는 연결 가능 여부를 확인하며, 진행 중 20분 이내 보고·빌드/AVD 직렬화를 지킨다.

- **Mac 사용 가능 통보 전에는 연결·전송·빌드·에뮬레이터 작업을 재개하지 않는다.**
- 재개 후 우선순위: 현재 Android 사용자 기준 TTS engine/초기화 원인 분리 → Console DDS 준비/좌석 콜백 왕복 → 실제 주행 제한/AudioFocus/복귀·창·성능 검사.

## 3. Release 서명키·최종 배포 자료

- 최신 사용자 결정: 기능 개발을 동결하고 기획서·승인 영상·소스·release APK 제출을 목표로 마무리한다. 키와 암호는 사용자 Mac 로컬에서 생성·보관하며 Hermes는 unsigned release 준비와 안전한 로컬 서명 절차를 제공한다. 사용자 키 없이 정상 서명 release가 있다고 주장하지 않는다.
- 기존 서명키가 있으면 안전한 로컬 경로와 사용 방식만 확인한다. **비밀번호·keystore·개인키를 채팅이나 Git에 넣지 않는다.**
- 기존 키가 없다면 프로젝트 전용 release 서명키 생성·보관 방식을 사용자와 확정한다. 사용자가 보관/복구할 수 없는 임시 키로 최종본을 만들지 않는다.
- 현재 debug와 unsigned release는 정상 release 제출물이 아니다. 서명·설치 검증 후에만 공모전 release 파일명을 적용한다.
- 저장소 접근 경로는 최신 공식 제출 안내로 확인한다. 심사자 Collaborator 초대를 필수 조건으로 가정하지 않으며 공개 범위 변경/초대는 자동으로 수행하지 않는다.
- 서명키 생성 완료는 아직 확인하지 않았다. 로컬 생성·백업·서명 안내: `design/RELEASE_SIGNING_GUIDE.md`. 비밀번호와 키 파일을 채팅으로 받지 않는다.

## 4. 실제 접수 승인

- 2026-11-13 사용자가 최종 코드의 기존 저장소 commit/push와 APK 업로드를 승인했다. force push·저장소 공개 범위 변경·새 계정/비용·사용자 동의/서명·실제 이메일 발송 승인은 포함하지 않는다. release가 지연돼도 필수 서류·승인 영상을 먼저 접수하는 방안을 채택했다.

- 서명한 최종 양식·선택 첨부·링크·발신자·수신자·제목을 확인한 뒤 실제 이메일 접수를 별도 승인한다.
- `email-submission-draft.md`는 미발송 초안이다. 자동 제출이나 접수 확인을 완료했다고 표시하지 않는다.
- 마감은 **2026-11-15 23:59 KST**. 영상/GitHub/APK가 덜 준비됐더라도 필수 서류 접수 자체를 지연시킬 필요는 없다.

## 5. 기존 노출 시크릿 정리

이전에 대화로 전달한 Playground client secret은 소유자가 콘솔에서 폐기·재발급하는 것을 권장한다. 교체 완료를 아직 확인하지 못했다. 해당 값은 재출력하거나 소스에 넣지 않았고, 현재 Vehicle 좌석 읽기·Android TTS 경로에 필요하지 않다. 새 시크릿도 채팅으로 전달할 필요가 없다.
